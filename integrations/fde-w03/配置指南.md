# FDE W03 工程测试配置指南

> 适用：`fde-student-w03-0.1.0-c16.zip`（已解压至 `~/Downloads/W03/工程/fde-student-w03/fde-agent-w03`）
> 本目录（`fde-w03-integration/`）是把该工程接进 `agent_eval` 批量测试框架的适配层。

## 这个工程自带三层测试，先分清

| 层 | 入口 | 用途 | 是否需要模型 API |
|---|---|---|---|
| 单元测试 | `.venv/bin/python -m pytest tests/ -q` | 平台代码离线回归 | 否 |
| 样例闭环 | `tools/w03.py doctor` / `load` / `test` | 梧桐样例指标库端到端 | **是** |
| 真实基线 | `evals/` + Promptfoo | W1 场景的 live baseline | **是** |
| 本框架 | 本目录 `run_eval.py` | 批量评估集 + 门禁 + 归因 | **是** |

课程要求的正式作业链路是 `w03.py test --cases customer/w03/tests.json --judge-command ...`，
**判定程序（judge.py）必须自己写**（默认报 `STUDENT_JUDGE_REQUIRED`）。本框架不替代它，
而是补上它没有的：批量门禁、blocker 一票否决、失败归因、版本留痕。

## 一、环境配置（已在本机实测走通）

### 1.1 用 arm64 的 Python 3.11，不要用 /usr/local/bin/python3.11

本机 `/usr/local/bin/python3.11` 是 **x86_64 版**（Rosetta 下运行），pip 只能找
`macosx_26_0_x86_64` 轮子，dbt 的 Rust 解析器无对应轮子 → 退化成源码编译 → 卡死 30 分钟。

正确做法（uv 自动装原生 arm64 3.11）：

```bash
cd ~/Downloads/W03/工程/fde-student-w03/fde-agent-w03
mv .venv .venv.old 2>/dev/null
uv python install 3.11
uv venv --python 3.11 .venv
.venv/bin/python -c "import platform;print(platform.machine(), platform.python_version())"
# 期望输出: arm64 3.11.15
```

### 1.2 dbt 解析器 wheel 必须走 GitHub 代理

`dbt_core_experimental_parser` 的 wheel（47MB）托管在 GitHub Releases，国内直连超时。
先下载再装（`gh-proxy.com` 实测 1.2MB/s）：

```bash
curl -L -o /tmp/dbt_core_experimental_parser-2.0.5-py3-none-macosx_11_0_arm64.whl \
  "https://gh-proxy.com/https://github.com/dbt-labs/dbt/releases/download/v2.0.5/dbt_core_experimental_parser-2.0.5-py3-none-macosx_11_0_arm64.whl"

VIRTUAL_ENV=.venv uv pip install /tmp/dbt_core_experimental_parser-2.0.5-py3-none-macosx_11_0_arm64.whl
VIRTUAL_ENV=.venv uv pip install -r requirements-w03.txt \
  --index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

> 注意：这个 wheel 里是**一个 137MB 的独立二进制**（`dbt-core-experimental-parser`），
> 不是 Python 模块，`import dbt_core_experimental_parser` 报 ModuleNotFoundError 属正常。

### 1.3 验证

```bash
.venv/bin/python tools/w03.py doctor
```

实测输出：

```json
{"python": "3.11.15", "missing_dependencies": [], "model_configured": false, "network_call_performed": false}
```

`model_configured: false` 是因为还没配模型——正常，见第二步。

## 二、模型配置（必填，密钥不进版本库）

### 2.1 跑 `run_eval.py` 要不要配 API？要，但不是在跑脚本的那个终端配

传清楚这件事：**`run_eval.py` 自己一次大模型都不调，但它调的被测 Agent 全程都在调。**

| 谁在调模型 | 调不调 | 说明 |
|---|---|---|
| `run_eval.py` / `adapter.py` / `harness.py` | **不调** | 全部确定性断言（4 条用例的 `judge_criteria` 都是空，不走语义判分） |
| W03 被测服务（`product.py start` 起的进程） | **每条用例都在调** | 意图识别 → 指标选型 → 结果汇总，一条问题通常 2~4 次模型调用 |

所以：

- **零判分费用**——本框架不产生「LLM 评判 LLM」那一层成本；
- **有被测成本**——每条用例都要真跑一次 Agent。4 条 ≈ 10 次调用，扩到 100 条就是 250 次左右，`pass^k` 复跑再乘 k。这块钱要单独立预算（对应方案 v2.0 的 3.3 测试自身成本）。

**关键点：环境变量必须配在「启动服务」的那个 shell，不是「跑脚本」的那个 shell。**

原因在 `tools/product.py` 第 31 行——服务启动时就构造模型客户端：

```python
model = CompatibleModel(timeout=90)          # 构造时读 os.environ
```

而 `CompatibleModel.__init__` 里 `FDE_MODEL_URL/NAME/KEY` 缺任意一项就抛 `MODEL_NOT_CONFIGURED`，进程直接退出。**服务根本没起来**，`run_eval.py` 只会看到「服务不在线」然后 `exit 2`——这时候你去查评估集、查断言、查适配器全是白费，问题在第一步。

### 2.2 配置方式

```bash
export FDE_MODEL_URL="https://你的兼容端点/v1/chat/completions"
export FDE_MODEL_NAME="模型名"
export FDE_MODEL_KEY="sk-..."
# 课程网关: export FDE_MODEL_PROFILE=gateway-low
```

同一个终端里紧接着 `product.py start`，两者必须在同一进程环境里。换个窗口跑脚本没关系，服务已经把配置读进内存了。

端点必须支持**原生工具调用**（Chat Completions 的 `tools`/`tool_calls`），否则指标查询这类工具型链路跑不通——`doctor` 查不出这一点，它只看变量在不在。

**这把 key 是学员自备的，课程不发密钥。** 工程文档原文：

> 本工具由学员配置自己的 Chat Completions 地址、模型名和密钥……不读取教师凭据，不自动切换供应商。（`docs/model-configuration.md`）
> 密钥不写入作业和版本库。（`docs/w03/README.md`）

课程提供的是「已验证的 profile 模板」（`gateway-low` / `deepseek-low` / `json-object` 等格式适配），以及访谈网站的账号与额度——**不是**模型凭据。若课程通知里给了网关地址和 key，按 `gateway-*` 配；没有就自备一个兼容端点。

### 2.3 配置生效怎么验（别信 doctor）

`doctor` 的 `model_configured` 只判断三个变量存在，**不发网络请求**（`network_call_performed: false`）。真正的验证是问一句：

```bash
curl -s -X POST http://127.0.0.1:8765/api/run \
  -H 'Content-Type: application/json' -H 'X-FDE-Client: local-ui' \
  -d '{"text":"2026 年 8 月梧桐书店扣退后收入是多少？","session":"probe-1"}'
```

返回体里有 `model_name` 且 `result.rows` 非空，才算真的通了。

### 2.4 故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `product.py start` 立刻退出，打印 `MODEL_NOT_CONFIGURED` | 三个变量有缺项，或不在同一 shell | 回到 2.2 重配，确认在启动服务的终端 |
| `run_eval.py` 报「服务不在线」`exit 2` | 服务没起 / 起的过程中退出 | 先看服务端日志，再回头看 2.1 |
| 服务在，但每条用例都失败在工具选择 | 端点不支持原生工具调用 | 换模型或换 profile |
| 单条用例耗时 > 90s 报 `MODEL_TIMEOUT` | 模型慢或输出预算被打满 | `export FDE_MODEL_TIMEOUT=180` 后重启服务 |

> 密钥别写进任何 `.py`/`.json`/作业文件。工程 README 明确要求：密钥只走环境变量，不写入版本库。

## 四、用本框架跑批量测试

```bash
cd ~/WorkBuddy/2026-11-06-16-00-03/Agent测试方案/fde-w03-integration

python3 selfcheck_offline.py                 # ① 离线自检，不需要模型 key
python3 run_eval.py                          # ② 真跑全量 18 条 + 门禁
python3 run_eval.py --evalset evalset_w03_smoke.json   # 4 条冒烟
python3 run_eval.py --baseline 0.9           # 相对基线门禁
```

**评测集分工**：

| 文件 | 条数 | 用途 |
|---|---|---|
| `evalset_w03.json` | 18（blocker 4 / major 12 / minor 2） | 默认全量，含边界含等于、空值、漏行、半开区间、筛选、拒答、澄清、分组 |
| `evalset_w03_smoke.json` | 4 | 冒烟，覆盖 ok / clarify / unsupported 三态，CI 快速门禁用 |

详细设计（手算底账 + 覆盖矩阵 + 每条用例的推导）见 `测试集设计说明.md`。

**断言路径有个坑**：指标数据在 `response.result.metric_query` 下，不在 `response.result` 下。
`result.status` 是 Agent 层（completed/clarification/refused/incomplete），
`result.metric_query.status` 才是引擎层（ok/clarify/unsupported/error）。

`selfcheck_offline.py` 用契约级假响应验证三件事：断言路径存在、harness 求值正确、门禁判定正确
（含两个负向用例：篡改 blocker 金额、把 cancelled 单误计入——都必须被拦截）。实测 18/18、4/4 全过。

## 五、适配器做了什么（adapter.py）

- HTTP POST `/api/run`，带工程强制的 `X-FDE-Client: local-ui` 头（缺了 403）
- 每条用例独立 `session_id`，避免会话串扰
- 响应映射：`result.metric_query.answer` → 输出文本；`observations` → 工具轨迹；
  整个响应入 `state["response"]`，并把 `metric_query` 提到 `state["metric"]` 方便短路径断言
- 版本四要素自动留痕：`model_name` / `prompt_sha256` / `product_version` / `runtime_revision`

## 六、青禾作业怎么扩

1. 把 `evalset_w03.json` 换成你自己的青禾测试集（期望必须基于 `materials/data/small`
   独立手算，禁止照抄运行结果——工程文档原文要求）
2. `--base-url` 不变（聊天入口复用），换加载的库即可
3. 课程提交仍用 `tools/w03.py test + judge.py` 链路；本框架的评估集与门禁报告可作为
   方案 8 章"证据留存"的附件
