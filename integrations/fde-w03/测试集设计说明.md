## 三、断言口径说明（先看这节：响应结构有个坑）

`/api/run` 返回的是 `agent.run()` 的 `safe` 字典（`platform/fde_product/agent.py:212`），**指标数据不在 `result` 下，而在 `result.metric_query` 下**：

```
response.status                                  → Agent 层：completed / clarification / refused / incomplete
response.result.metric_query.status              → 引擎层：ok / clarify / unsupported / error
response.result.metric_query.rows                → 数值行
response.result.metric_query.units.<metric_id>   → 单位（cents / count / ratio）
```

两层状态含义不同：Agent 层 `refused` 对应引擎层 `unsupported`，`clarification` 对应 `clarify`。
断言一律写 `response.result.metric_query.*`，**不要写 `response.result.rows`**——按后者写会永远是 `None`，
表现成"Agent 没答对"，实际是断言路径错了。

其余口径：

- 数值类全部走 `state_after` 点路径锁 `rows`，`units.*` 锁单位
- #16 分组用 `min_length: 2` + `judge_criteria`，因为 MetricFlow 返回的分组行序不保证稳定，行内容交给 judge 核对「门店 8000 / 小程序 5000」
- #17 比率只锁单位 + `response_contains ["13"]`（0.1333 和 13.33% 都含"13"），精确数值留给 judge
- #6 多指标假设列序跟随提问顺序；若模型换了提问顺序导致列序颠倒，把 rows 改成 [[13000, 23000]] 对应顺序即可（或拆成两条单指标）

## 四、已知的行为分歧点（跑批前先读，免得误判为 bug）

| 用例 | 可能的合理分歧 | 处理 |
|---|---|---|
| #15 天猫渠道 | 模型可能不构造 filter 而直接澄清"没有天猫渠道" | `clarify` 精神上也算过；判 fail 时先看 answer 文本再定 |
| #18 歧义收入 | 模型可能直接选净收入答 13000 | 这算"没澄清"，按 fail 记录；是否改判由你定（课程口径倾向必须澄清） |
| #4 六月占比 | 引擎返回 rows=[[null]]，但 answer 文本可能说"无数据" | rows 断言是硬的；answer 措辞不管 |
| #10 同义改写 | 「净收入」在 catalog 里没有别名，全靠模型对齐 | 挂了说明别名/提示词要补，这正是这条用例存在的意义 |

## 五、运行

```bash
# ① 先离线自检：不需要模型 key，验证断言路径与门禁逻辑
cd ~/WorkBuddy/2026-11-06-16-00-03/Agent测试方案/fde-w03-integration
python3 selfcheck_offline.py
# 期望：全量 18/18 ✅、冒烟 4/4 ✅、篡改金额 ⛔ 拦截、撤销单误计 ⛔ 拦截

# ② 服务起来之后（start_service.sh）再真跑
python3 run_eval.py                                   # 全量 18 条（默认）
python3 run_eval.py --evalset evalset_w03_smoke.json   # 4 条冒烟，约 1/4 时间
python3 run_eval.py --baseline 0.9                    # 相对基线门禁
```

`selfcheck_offline.py` 用「契约级假响应」跑通全链路，假响应形状照 `agent.py:212` 的 safe 字典构造，
数值取自本文第一节的手算底账（独立于评估集文件，不是从断言反推）。它证明的是**断言路径对、harness 求值对、
门禁判定对**，不证明 Agent 答得对——后者必须真跑。

真跑时 blocker 4 条里任何一条失败直接拦截合并，不看总成功率。`judge_criteria` 字段当前框架在 L0 不执行，
是给后续接 LLM judge（先过金标集校准）和课程 `w03.py test --judge-command` 链路复用的。
